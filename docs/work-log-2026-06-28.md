## 1. [CRITICAL] Action Datatable Tidak Berfungsi di Halaman Published

### Masalah
Saat halaman yang sudah di-publish dibuka, tombol **View**, **Edit**, dan **Delete** pada datatable tidak merespon ketika diklik. Halaman terlihat seperti statis/dummy.

### Lokasi
- **File:** `services/MasterDatatableRenderService.php`
- **Baris:** ~1554-1558 (JS inline dalam method `renderFromConfig`)

### Root Cause
Terdapat **syntax error JavaScript**. Di dalam kode JS inline yang di-generate PHP, ada literal `\n` + `\t` yang ditulis sebagai:

```javascript
'...\n' +
'\t\t\t...'
```

Karena kode ini berada di dalam string PHP (single-quoted atau heredoc), karakter `\n` dan `\t` di-interpretasikan oleh PHP sebagai **newline literal** dan **tab literal**, bukan sebagai string literal `\n` dan `\t`. Akibatnya JavaScript yang dihasilkan mengandung baris baru dan tab asli di dalam string, menyebabkan syntax error dan seluruh script inline tidak tereksekusi.

### Fix
Escape `\n` menjadi `\\n` dan `\t` menjadi `\\t` sehingga PHP menghasilkan string literal `\n` dan `\t` di output JavaScript:

```javascript
// SEBELUM (salah)
'...\n' +
'\t\t\t...'

// SESUDAH (benar)
'...\\n' +
'\\t\\t\\t...'
```

### Dampak
✅ Setelah fix, semua tombol aksi (View, Edit, Delete) di datatable berfungsi normal di halaman yang sudah di-publish.

## 2. [CRITICAL] Display Mode "Image" Menampilkan Sel Kosong

### Masalah
Saat kolom datatable diubah display_mode-nya dari `text` ke `image`, sel yang tadinya menampilkan URL path sekarang menjadi kosong. Gambar tidak muncul.

### Lokasi
- **File:** `services/MasterDatatableRenderService.php`
- **Baris:**
  - PHP: `renderCellValue()` ~2354
  - JS: `buildRowCellsHtml()` ~1320
  - JS: `formatViewValue()` ~1463

### Root Cause
Nilai yang disimpan di database adalah **relative path**, contoh:

```
forms/gps-camera/13/gps-field_6_20260628122651_76dd7c47.jpg
```

Ketika digunakan sebagai `src` pada tag `<img>`, browser menafsirkan path tersebut relatif terhadap URL halaman saat ini. Misal halaman di `/page/view/14`, browser akan mencari:

```
/page/view/forms/gps-camera/13/gps-field_6_20260628122651_76dd7c47.jpg
```

Padahal file sebenarnya berada di:

```
/uploads/workspace/forms/gps-camera/13/gps-field_6_20260628122651_76dd7c47.jpg
```

### Struktur Storage (WorkspaceMediaStorage)

```
Storage (primary):
  @storage/uploads/forms/gps-camera/{formId}/gps-{field}_{timestamp}_{random}.jpg
  Contoh: /app/storage/uploads/forms/gps-camera/13/gps-field_6_1782662100_3f3a0c4a.jpg

Public (mirror):
  @webroot/uploads/workspace/forms/gps-camera/{formId}/gps-{field}_{timestamp}_{random}.jpg
  Contoh: /app/web/uploads/workspace/forms/gps-camera/13/gps-field_6_1782662100_3f3a0c4a.jpg

URL publik:
  /uploads/workspace/forms/gps-camera/{formId}/gps-{field}_{timestamp}_{random}.jpg
```

### Fix: Normalisasi URL

**A. PHP — `normalizeAssetUrl()` (method private, ~baris 2648)**

```php
private const ASSET_BASE_URL = '/uploads/workspace/';

private function normalizeAssetUrl(string $url): string
{
    if ($url === '') return $url;
    if (preg_match('#^(https?://|//|/)#i', $url)) return $url;
    return self::ASSET_BASE_URL . ltrim($url);
}
```

**B. JS — `normalizeAssetUrl()` (inline function, ~baris 1306)**

```javascript
function normalizeAssetUrl(url) {
    if (!url) return url;
    if (/^(https?:\/\/|\/\/|\/)/i.test(url)) return url;
    return (payload.assetBaseUrl || '/uploads/workspace/') + url;
}
```

**C. Endpoint yang diupdate:**

| Fungsi | Mode | Lokasi |
|--------|------|--------|
| `renderCellValue()` (PHP) | image, file, link | Baris ~2354-2388 |
| `buildRowCellsHtml()` (JS) | image, file, link | Baris ~1320-1330 |
| `formatViewValue()` (JS) | image, file, link | Baris ~1463-1480 |

**D. Payload JS — tambah `assetBaseUrl`**

```php
'assetBaseUrl' => self::ASSET_BASE_URL,
```

Ditambahkan ke `$payload` di konstruksi inline script.

### Logika Normalisasi

| Nilai di DB | Hasil `src` | Keterangan |
|-------------|-------------|------------|
| `forms/gps-camera/13/photo.jpg` | `/uploads/workspace/forms/gps-camera/13/photo.jpg` | ✅ Relatif → ditambahi prefix |
| `/uploads/workspace/forms/photo.jpg` | `/uploads/workspace/forms/photo.jpg` | ✅ Sudah absolut (diawali `/`) |
| `http://example.com/photo.jpg` | `http://example.com/photo.jpg` | ✅ Sudah URL absolut |
| `https://example.com/photo.jpg` | `https://example.com/photo.jpg` | ✅ Sudah URL absolut |

### Dampak
✅ Display mode Image sekarang menampilkan gambar dengan benar di:
- Tampilan tabel datatable (initial render PHP)
- Tampilan tabel datatable (AJAX row update JS)
- View modal (detail baris)

## 3. [MEDIUM] Inkonsistensi Nama File Upload GPS Camera

### Masalah
Terdapat dua jalur upload foto GPS camera yang menggunakan format timestamp berbeda, menyebabkan nama file di database tidak cocok dengan nama file di disk.

### Lokasi
- **File:** `controllers/MasterFormController.php`
- **File:** `controllers/FormController.php`
- **Method:** `storeGpsCameraBase64Image()` di kedua controller

### Root Cause

| Jalur | Method | Format Nama File | Contoh |
|-------|--------|-----------------|--------|
| PATH A (multipart) | `WorkspaceMediaStorage::storeUploadedFile()` via `$_FILES` | `time()` — Unix timestamp | `gps-field_6_1782662100_3f3a0c4a.jpg` |
| PATH B (base64) | `storeGpsCameraBase64Image()` via `photo_data` | `date('YmdHis')` — format YYYYMMDDHHMMSS | `gps-field_6_20260628122651_76dd7c47.jpg` |

Kedua jalur menggunakan format timestamp yang berbeda. Untuk momen yang sama:
- PATH A: `gps-field_6_1782662100_3f3a0c4a.jpg`
- PATH B: `gps-field_6_20260628122651_76dd7c47.jpg`

### Alur Upload (Form Submit)

```
User capture foto
  ↓
Client-side:
  - File object disimpan di <input type="file" name="__gps_camera_file_{fieldName}">
  - Base64 data URL disimpan di <input type="hidden" name="{fieldName}"> sebagai JSON
  ↓
Form submit (POST /master-form/submit/{id})
  ↓
applyGpsCameraProcessing() di MasterFormController:
  1. Cek PATH A: UploadedFile::getInstanceByName('__gps_camera_file_{name}')
     - Jika ada: storeUploadedFile() → simpan dengan time() + set photo_path
  2. Cek PATH B: jika photo_path belum diset DAN ada photo_data
     - Jika ada: storeGpsCameraBase64Image() → simpan dengan date('YmdHis') + set photo_path
  3. Mapping: photo_path → kolom target di tabel
```

### Fix
Ubah `date('YmdHis')` menjadi `time()` di:

**MasterFormController.php** (~baris 3584):
```php
// SEBELUM
$fileName = 'gps-...' . date('YmdHis') . '_' . bin2hex(random_bytes(4)) . '.' . $extension;

// SESUDAH
$fileName = 'gps-...' . time() . '_' . bin2hex(random_bytes(4)) . '.' . $extension;
```

**FormController.php** (~baris 1281):
```php
// SAMA: date('YmdHis') → time()
```

### Dampak
✅ Mulai sekarang, kedua jalur upload menghasilkan format nama file yang sama (Unix timestamp). Inkonsistensi tidak akan terjadi lagi untuk upload baru.

## 4. [INFO] File Tidak Persisten di Container Docker (Coolify)

### Temuan
Folder `/app/web/uploads/workspace/forms/gps-camera/13/` yang sebelumnya ada (berisi 2 file) tiba-tiba hilang. File login background (`login_bg_1778935078_2413dc98.mp4`) masih ada karena di-upload setelah container terakhir restart.

### Penyebab
Container Docker di Coolify kemungkinan **tidak memiliki persistent volume** untuk folder `web/uploads/workspace/`. Ketika container di-restart atau di-redeploy, semua file yang diupload setelah container start akan hilang.

### Data di Database vs File di Disk
- **Login background:** Ada di DB ✅, Ada di disk ✅ (diupload setelah restart)
- **GPS camera (form 13):** Ada di DB ✅, Tidak ada di disk ❌ (diupload sebelum restart, hilang)

### Rekomendasi
1. **Konfigurasi Coolify persistent volume** untuk folder `web/uploads/workspace/`
2. Atau **simpan gambar sebagai base64 di database** agar tidak bergantung pada filesystem container

## 5. [MEDIUM] View Modal Datatable Tidak Menampilkan Gambar

### Masalah
Saat tombol View diklik pada baris datatable, modal detail baris terbuka. Field dengan display_mode `image` menampilkan tag `<img>` dengan `src` yang salah (relative path tanpa prefix).

### Lokasi
- **File:** `services/MasterDatatableRenderService.php`
- **Fungsi:** `formatViewValue()` — JS inline ~baris 1463-1469

### Root Cause
Fungsi `formatViewValue()` sudah mendeteksi display_mode `image` dan merender tag `<img>`, tetapi menggunakan raw value dari database langsung sebagai `src` tanpa normalisasi URL.

### Fix
Tambahkan panggilan `normalizeAssetUrl()` untuk mode **image**, **file**, dan **link**:

```javascript
// SEBELUM
if (displayMode === 'image') {
    const url = String(value);
    ...
    return '<img src="' + escapeHtml(url) + '" ...>';
}

// SESUDAH
if (displayMode === 'image') {
    const url = normalizeAssetUrl(String(value));
    ...
    return '<img src="' + escapeHtml(url) + '" ...>';
}
```

### Dampak
✅ View modal sekarang menampilkan gambar dengan URL yang benar.

### Debugging

Untuk debug GPS camera upload, cek log aplikasi:
```bash
grep -i "gps_camera\|photo_path\|storeGpsCamera\|DEBUG_VERIFY" /app/runtime/logs/app.log
```

### Coolify Persistent Storage

Untuk mencegah file hilang saat container restart, tambahkan persistent volume di Coolify:

1. Buka Coolify dashboard → Service → Configuration
2. Tambah Volume Mount:
   - **Path di container:** `/app/web/uploads/workspace`
   - **Type:** `volume` atau `bind`
3. Deploy ulang
